1. Objectifs et contexte

L'objectif est de construire une chaîne CI/CD pédagogique permettant de récupérer une application Java depuis Git, de la compiler avec Maven, d'exécuter les tests puis de déployer l'artefact WAR sur Apache Tomcat avec Jenkins.

  • Comprendre le rôle du contrôleur Jenkins et de ses agents.
  • Automatiser build et tests Maven.
  • Produire un artefact reproductible.
  • Déployer l'application sur Tomcat.
  • Versionner le pipeline dans Git.
CI/CD : la CI valide le code par compilation et tests ; le CD automatise la livraison vers l'environnement cible.

2. Prérequis

  • Ubuntu 24.04 LTS ou Debian récent.
  • Java 21 pour Jenkins.
  • Accès réseau aux dépôts Jenkins, Maven et Git.
  • Projet Java/Maven avec pom.xml.
  • Serveur Tomcat accessible depuis l'agent Jenkins.
  • Ports adaptés au laboratoire : 8080 pour Jenkins/Tomcat ; en production, privilégier HTTPS via reverse proxy.

Pour une petite équipe, Jenkins recommande environ 4 Go de RAM et 50 Go de stockage.

3. Concepts et architecture

4. Installation et configuration

4.1 Java 21

sudo apt update sudo apt install -y fontconfig openjdk-21-jre java -version

4.2 Jenkins LTS

sudo mkdir -p /etc/apt/keyrings sudo wget -O /etc/apt/keyrings/jenkins-keyring.asc https://pkg.jenkins.io/debian-stable/jenkins.io-2026.key echo "deb [signed-by=/etc/apt/keyrings/jenkins-keyring.asc] https://pkg.jenkins.io/debian-stable binary/" | sudo tee /etc/apt/sources.list.d/jenkins.list > /dev/null sudo apt update sudo apt install -y jenkins sudo systemctl enable --now jenkins sudo systemctl status jenkins

Le paquet Jenkins utilise systemd et écoute par défaut sur 8080. Le secret initial est récupérable avec :

sudo cat /var/lib/jenkins/secrets/initialAdminPassword

4.3 Maven

sudo apt install -y maven mvn --version

La version des dépôts peut varier. Maven 3.9.16 est actuellement une référence stable ; Jenkins peut également gérer Maven via Manage Jenkins → Tools.

4.4 Tomcat

sudo apt install -y tomcat10 sudo systemctl enable --now tomcat10 sudo systemctl status tomcat10 curl -I http://localhost:8080

Tomcat 10.1 est une branche stable. Une application ancienne basée sur javax.* peut nécessiter une migration vers jakarta.*.

5. Réalisation pratique

5.1 Build Maven local

mvn -B clean test package ls -lh target/*.war

5.2 Pipeline Jenkins

Créer un pipeline relié au dépôt Git puis ajouter le Jenkinsfile à la racine :

pipeline { agent any stages { stage('Checkout') { steps { checkout scm } } stage('Build') { steps { sh 'mvn -B clean package' } } stage('Test') { steps { sh 'mvn -B test' } post { always { junit '**/target/surefire-reports/*.xml' } } } stage('Archive') { steps { archiveArtifacts artifacts: 'target/*.war', fingerprint: true } } stage('Deploy') { when { branch 'main' } steps { sh 'scp target/*.war deploy@TOMCAT_HOST:/tmp/app.war' sh 'ssh deploy@TOMCAT_HOST "sudo mv /tmp/app.war /var/lib/tomcat10/webapps/app.war"' } } } post { always { deleteDir() } } }

En pratique, utiliser Jenkins Credentials et des variables d'environnement pour l'hôte, la clé SSH et les secrets.

7. Vérifications et tests

  1. java -version.
  2. systemctl is-active jenkins.
  3. mvn --version.
  4. systemctl is-active tomcat10.
  5. curl -I http://localhost:8080.
  6. Exécuter le pipeline et vérifier Checkout, Build, Test, Archive et Deploy.
  7. Tester l'application avec curl -I http://TOMCAT_HOST:8080/app/.
  8. Vérifier les rapports JUnit et le WAR archivé.
Critère de succès : une erreur de compilation ou de test doit bloquer le déploiement.

9. Sécurité et bonnes pratiques

  • Utiliser Jenkins LTS et maintenir les plugins à jour.
  • Protéger Jenkins par HTTPS, authentification forte et filtrage réseau.
  • Stocker clés, tokens et mots de passe dans Jenkins Credentials.
  • Utiliser un compte de déploiement dédié avec privilèges minimaux.
  • Éviter un accès sudo généraliste pour le compte de déploiement.
  • Utiliser des agents isolés pour les builds.
  • Limiter la conservation des anciens builds et artefacts.
  • Déployer uniquement après validation des tests.
  • Ne pas exposer le Tomcat Manager publiquement.
  • Sauvegarder la configuration Jenkins et surveiller les logs.

11. Conclusion

La chaîne CI/CD associe Git, Jenkins, Maven et Tomcat afin d'automatiser le cycle de livraison d'une application Java. Le pipeline devient reproductible, auditable et contrôlable.

Pour une plateforme de production, compléter cette base par des agents isolés, HTTPS, gestion stricte des secrets, contrôles de qualité, rollback, observabilité et déploiement progressif.
