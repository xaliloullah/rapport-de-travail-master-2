Complément académique — AWS CodeCommit

Gestion de versions, collaboration et gouvernance du code source.

1. Contrôle de version

Un dépôt Git conserve l'historique des modifications et permet de revenir à un état antérieur. Dans une démarche académique, cet historique constitue également une trace des travaux réalisés.

2. Collaboration

Les branches permettent d'isoler les fonctionnalités. Les revues de code et règles de fusion réduisent les risques d'intégrer une modification incorrecte dans la branche principale.

git status
git log --oneline --graph --decorate
git branch -a
git fetch --all

3. Sécurité du dépôt

  • Ne jamais versionner de secrets.
  • Limiter les permissions d'écriture.
  • Utiliser des branches protégées lorsque le contexte le permet.
  • Conserver une convention de commits claire.

4. Analyse critique

Le contrôle de version n'est pas seulement une sauvegarde. Il structure le processus de développement : traçabilité, revue, expérimentation et intégration. Le dépôt doit donc être considéré comme un composant de gouvernance du cycle de vie logiciel.

5. Questions d'évaluation

  1. Pourquoi créer des branches ?
  2. Quelle différence entre dépôt local et dépôt distant ?
  3. Pourquoi les secrets ne doivent-ils pas être commités ?
  4. Quel rôle joue la revue de code ?
