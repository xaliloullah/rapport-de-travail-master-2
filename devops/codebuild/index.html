1. Objectifs et contexte

AWS CodeBuild est un service CI managé qui compile le code, exécute les tests et produit des artefacts sans imposer l'administration d'un serveur de build permanent.

  • Automatiser compilation et tests.
  • Produire des artefacts reproductibles.
  • Centraliser logs et rapports.
  • Intégrer le build dans une chaîne CI/CD avec CodeCommit, GitHub, CodePipeline et CodeDeploy.
Rôle : CodeBuild constitue principalement la brique build / test / package de la chaîne DevOps.

2. Prérequis

  • Compte AWS et région de travail.
  • Accès IAM permettant d'administrer/exécuter CodeBuild selon le besoin.
  • Dépôt Git contenant le projet.
  • buildspec.yml à la racine du dépôt, sauf configuration contraire.
  • Projet Java/Maven pour l'exemple.
  • Bucket S3 si les artefacts doivent être exportés.
aws sts get-caller-identity aws configure get region aws codebuild list-projects --region us-east-1

4. Installation et configuration

  1. CodeBuild → Create build project.
  2. Nom : m2-application-build.
  3. Sélectionner la source.
  4. Choisir une image CodeBuild maintenue et un runtime compatible.
  5. Associer un rôle IAM dédié.
  6. Activer CloudWatch Logs.
  7. Configurer artefacts et cache si nécessaires.
version: 0.2 phases: install: runtime-versions: java: corretto17 commands: - java -version - mvn -version build: commands: - mvn -B clean verify post_build: commands: - echo "Build terminé" reports: junit-reports: files: - 'target/surefire-reports/*.xml' file-format: JUNITXML artifacts: files: - target/*.jar cache: paths: - '/root/.m2/**/*'
Bon réflexe : versionner le buildspec avec le code et spécifier explicitement le runtime afin de rendre le build plus reproductible.

5. Réalisation pratique

Préparer le dépôt

git clone https://example.com/mon-projet.git cd mon-projet mvn -B test ls -la buildspec.yml

Lancer un build

aws codebuild start-build --project-name m2-application-build --region us-east-1

Architecture CI/CD

Le dépôt fournit le code, CodeBuild compile et teste, puis l'artefact est transmis à l'étape suivante du pipeline.

6. Commandes et explications

aws codebuild list-projects --region us-east-1 aws codebuild batch-get-projects --names m2-application-build --region us-east-1 aws codebuild start-build --project-name m2-application-build --region us-east-1 aws codebuild batch-get-builds --ids BUILD_ID --region us-east-1

list-projects liste les projets ; batch-get-projects inspecte leur configuration ; start-build déclenche une exécution ; batch-get-builds permet de consulter son résultat.

7. Vérifications et tests

aws codebuild batch-get-builds --ids BUILD_ID --query 'builds[0].buildStatus' --output text --region us-east-1 mvn -B test mvn -B verify ls -la target/surefire-reports/

Le statut attendu pour un build correctement terminé est SUCCEEDED. Vérifier également les logs, les rapports JUnit et la présence de l'artefact.

Validation : un build réussi confirme l'exécution technique du processus, mais ne garantit pas à lui seul la qualité fonctionnelle de l'application.

Méthode : rechercher la première erreur significative dans les logs plutôt que de traiter la dernière ligne BUILD FAILED comme cause principale.

9. Sécurité et bonnes pratiques

  • Principe du moindre privilège pour le rôle IAM CodeBuild.
  • Aucun secret dans Git ou buildspec.yml.
  • Secrets Manager ou Parameter Store pour les secrets.
  • Chiffrement KMS des artefacts sensibles si nécessaire.
  • CloudWatch Logs pour l'audit.
  • Ne pas activer le mode privilégié sauf besoin réel, notamment pour Docker.
  • Fixer les versions importantes des runtimes/outils.
  • Séparer développement, recette et production lorsque nécessaire.
  • Définir une rétention des artefacts et caches.
IAM : le rôle de service CodeBuild agit sur les ressources AWS au nom du build ; une permission excessive augmente donc directement le périmètre d'action du processus.

11. Conclusion

CodeBuild automatise la compilation, les tests et la production d'artefacts dans un environnement managé. Le buildspec.yml formalise les étapes du processus et permet de versionner la logique de build avec le code.

Dans une architecture DevOps complète, CodeBuild est destiné à être associé à CodePipeline et à un mécanisme de déploiement tel que CodeDeploy. La sécurité repose sur le moindre privilège IAM, la protection des secrets, la maîtrise des artefacts et une configuration réseau adaptée.
