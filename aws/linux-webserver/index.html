1. Objectif

Ce guide détaille le déploiement d'un serveur web complet sur AWS EC2 en utilisant une distribution Linux (Amazon Linux 2). À la fin de ce document, vous disposerez :

  • D'une instance EC2 fonctionnelle sous Amazon Linux 2.
  • Du serveur web Apache (ou Nginx) installé et configuré.
  • D'une page web accessible publiquement via l'IP publique de l'instance.
  • D'un Security Group correctement configuré (HTTP 80, HTTPS 443).
Pourquoi Amazon Linux 2 ? Amazon Linux 2 est une distribution Linux maintenue par AWS, optimisée pour les instances EC2. Elle est gratuite, légère et inclut directement les outils de gestion (AWS Systems Manager, CloudWatch, etc.).

2. Création d'une instance EC2 Amazon Linux 2

Nous allons lancer une instance EC2 en suivant ces étapes :

  1. Accéder à la console AWS → Service EC2.
  2. Cliquer sur Lancer une instance.
  3. Nom de l'instance : webserver-linux.
  4. AMI : choisir Amazon Linux 2 (ou Amazon Linux 2023).
  5. Type d'instance : t2.micro (gratuit dans le Free Tier).
  6. Clé de paire : créer ou sélectionner un fichier .pem existant.
  7. Configurer le Security Group :

Configuration du Security Group

Type Protocole Source Description
SSH TCP 22 Mon IP Accès administrateur
HTTP TCP 80 Toute adresse IP (0.0.0.0/0) Accès web
HTTPS TCP 443 Toute adresse IP (0.0.0.0/0) Accès web sécurisé

Cliquer sur Lancer l'instance. L'instance démarre en quelques minutes :

Security Group : Le SG agit comme un pare-feu virtuel au niveau de l'instance. Seuls les ports nécessaires (SSH, HTTP, HTTPS) doivent être ouverts. Jamais de port administratif (ex. 3306, 5432) à 0.0.0.0/0 sans justification.

3. Connexion à l'instance

Une fois l'instance en état running, récupérer l'IP publique depuis le tableau des instances :

SSH depuis Linux / Mac :

chmod 400 mon-keypair.pem ssh -i "mon-keypair.pem" ec2-user@<PUBLIC_IP>

SSH depuis Windows (PowerShell) :

ssh -i "C:\chemin\mon-keypair.pem" ec2-user@<PUBLIC_IP>
Utilisateur : Sur Amazon Linux 2, l'utilisateur par défaut est ec2-user. Ne pas utiliser root directement pour des raisons de sécurité.

4. Installation du serveur Apache (httpd)

Nous allons installer Apache, le configurer pour démarrer au lancement et déployer une page web.

Étape 1 — Mettre à jour le système :

sudo yum update -y

Étape 2 — Installer Apache :

sudo yum install -y httpd
Amazon Linux 2 : utilise yum (basé sur RPM). Sur Ubuntu/Debian, on utiliserait apt au lieu de yum.

Étape 3 — Démarrer le service et l'activer au boot :

sudo systemctl start httpd sudo systemctl enable httpd

Étape 4 — Créer une page d'accueil :

sudo echo "<h1>Bienvenue sur mon serveur AWS !</h1> <p>Serveur Apache installé sur Amazon Linux 2</p>" | sudo tee /var/www/html/index.html

Vérification :

systemctl status httpd curl http://localhost

5. Alternative : Installation de Nginx

Nginx (prononcé "engine-x") est une alternative performante à Apache, souvent utilisée comme reverse proxy ou serveur statique.

sudo yum install -y nginx sudo systemctl start nginx sudo systemctl enable nginx # Page d'accueil sudo echo "<h1>Nginx sur AWS</h1>" | sudo tee /usr/share/nginx/html/index.html
Nginx vs Apache : Nginx est plus léger et mieux performante pour le streaming et les fichiers statiques. Apache est plus flexible pour les modules (mod_rewrite, .htaccess). Choisissez selon vos besoins.

6. Configuration du firewall et des ports

Le Security Group est déjà configuré (section 2). Nous pouvons aussi sécuriser l'instance avec firewalld :

# Vérifier firewalld sudo systemctl status firewalld # Autoriser HTTP et HTTPS sudo firewall-cmd --permanent --add-service=http sudo firewall-cmd --permanent --add-service=https # Recharger la configuration sudo firewall-cmd --reload # Vérifier les règles sudo firewall-cmd --list-all
Attention : Si vous activez un firewall supplémentaire (firewalld ou iptables), assurez-vous que les règles AWS Security Group et le firewall local sont cohérentes. Une règle bloquante dans l'un et non l'autre empêche la connexion.

7. Test du site web dans le navigateur

Depuis votre machine locale, saisissez l'IP publique de l'instance dans votre navigateur :

http://<PUBLIC_IP>
Astuce : Vous pouvez associer un nom de domaine à votre instance via une Elastic IP et un enregistrement DNS (Route 53 ou autre registrar) pour un accès plus professionnel.

8. Bonnes pratiques et sécurité

  • MFA : Activez l'authentification multi-facteurs sur le compte racine.
  • IAM : Utilisez un compte IAM avec le minimum nécessaire au lieu du compte racine.
  • Clé SSH : Protégez votre fichier .pem (chmod 400) et ne le partagez jamais.
  • Mises à jour : Maintenez le système à jour régulièrement (sudo yum update).
  • Sauvegarde : Créez des snapshots EBS réguliers de l'instance.
  • Monitoring : Activez CloudWatch pour surveiller l'utilisation CPU et les logs Apache via /var/log/httpd/.
  • SSL/TLS : Installez un certificat (Let's Encrypt) pour passer en HTTPS.
