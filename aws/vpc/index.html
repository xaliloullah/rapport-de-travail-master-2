1. Objectif

AWS VPC (Virtual Private Cloud) permet de lancer des ressources AWS dans un réseau virtuel isolé du reste de l'infrastructure AWS. Ce guide vous apprendra à :

  • Comprendre les concepts clés : VPC, sous-réseaux, route tables, IGW, NAT Gateway.
  • Créer un VPC personnalisé avec des sous-réseaux publics et privés.
  • Configurer la connectivité Internet pour les deux types de sous-réseaux.
  • Configurer des Security Groups et des Network ACLs pour la sécurité réseau.
Pourquoi un VPC personnalisé ? Le VPC par défaut est pratique pour commencer, mais un VPC personnalisé vous donne un contrôle total sur la topologie réseau, la sécurité et la gestion des adresses IP.

2. Concepts clés VPC

Élément Description
VPC Réseau virtuel isolé dans le cloud AWS (plage d'IP CIDR).
Sous-réseau (Subnet) Plage d'IP CIDR dans le VPC. Public = accès Internet, privé = pas d'accès direct.
Internet Gateway (IGW) Point d'accès vers Internet pour les sous-réseaux publics.
NAT Gateway Permet aux ressources privées d'accéder à Internet (sortie seulement).
Route Table Définit les règles de routage pour un ou plusieurs sous-réseaux.
Security Group Pare-feu au niveau de l'instance (état des connexions).
Network ACL Pare-feu au niveau du sous-réseau (stateless, plus restrictif).
Topologie recommandée : Un VPC avec 2 sous-réseaux publics (pour les serveurs web) et 2 sous-réseaux privés (pour les bases de données), derrière un NAT Gateway pour l'accès Internet sortant.

3. Création d'un VPC personnalisé

Nous allons créer un VPC avec la plage d'adresses 10.0.0.0/16 :

Étapes via la console :

  1. Aller dans la console EC2 → VPC → Your VPCs.
  2. Cliquer sur Create VPC.
  3. Saisir :
    • Nom : maire-vpc
    • IPv4 CIDR : 10.0.0.0/16
    • IPv6 CIDR : /56
  4. Cliquer sur Create.

Création via AWS CLI :

# Créer un VPC aws ec2 create-vpc \ --cidr-block "10.0.0.0/16" \ --tag-specifications 'ResourceType=vpc,Tags=[{Key=Name,Value=maire-vpc}]' # Récupérer l'ID du VPC créé aws ec2 describe-vpcs --filters "Name=tag:Name,Values=maire-vpc"
CIDR : 10.0.0.0/16 vous donne 65 534 adresses IP privées. Adaptez la taille selon le nombre de ressources prévues.

4. Sous-réseaux (Public & Private)

Nous allons créer 4 sous-réseaux : 2 publics et 2 privés dans des AZ différentes.

# Sous-réseau public AZ1 aws ec2 create-subnet \ --vpc-id vpc-xxxxxxxx \ --cidr-block "10.0.1.0/24" \ --availability-zone "us-east-1a" \ --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=public-subnet-1a}]' # Sous-réseau public AZ2 aws ec2 create-subnet \ --vpc-id vpc-xxxxxxxx \ --cidr-block "10.0.2.0/24" \ --availability-zone "us-east-1b" \ --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=public-subnet-1b}]' # Sous-réseau privé AZ1 aws ec2 create-subnet \ --vpc-id vpc-xxxxxxxx \ --cidr-block "10.0.3.0/24" \ --availability-zone "us-east-1a" \ --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=private-subnet-1a}]' # Sous-réseau privé AZ2 aws ec2 create-subnet \ --vpc-id vpc-xxxxxxxx \ --cidr-block "10.0.4.0/24" \ --availability-zone "us-east-1b" \ --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=private-subnet-1b}]'

5. Internet Gateway (IGW)

L'Internet Gateway fournit un accès bidirectionnel vers Internet pour les sous-réseaux publics.

# Créer une Internet Gateway aws ec2 create-internet-gateway \ --tag-specifications 'ResourceType=internet-gateway,Tags=[{Key=Name,Value=maire-igw}]' # Attacher l'IGW au VPC aws ec2 attach-internet-gateway \ --vpc-id vpc-xxxxxxxx \ --internet-gateway-id igw-xxxxxxxx

6. NAT Gateway

Le NAT Gateway permet aux ressources dans les sous-réseaux privés d'accéder à Internet (sortie uniquement), sans être directement accessibles depuis Internet.

Étapes :

  1. Allouer une Elastic IP pour le NAT Gateway.
  2. Créer le NAT Gateway dans un sous-réseau public.
  3. Mettre à jour la route table du sous-réseau privé pour router via le NAT.
# Allouer une Elastic IP aws ec2 allocate-address --domain vpc # Créer le NAT Gateway (dans le sous-réseau public) aws ec2 create-nat-gateway \ --subnet-id subnet-xxxxxxxx \ --allocation-id eipalloc-xxxxxxxx \ --tag-specifications 'ResourceType=nat-gateway,Tags=[{Key=Name,Value=maire-natgw}]'
Coût : Le NAT Gateway est facturé à l'heure près. Pour les environnements de dev/test, pensez à le désactiver ou utiliser un NAT d'instance (plus économique mais moins résilient).

7. Route Tables

Les route tables définissent comment le trafic sort du sous-réseau. Chaque route table peut être associée à un ou plusieurs sous-réseaux.

Route table publique :

# Créer une route table pour le VPC aws ec2 create-route-table --vpc-id vpc-xxxxxxxx # Ajouter une route vers l'IGW (accès Internet) aws ec2 create-route \ --route-table-id rtb-xxxxxxxx \ --destination-cidr-block "0.0.0.0/0" \ --gateway-id igw-xxxxxxxx # Associer au sous-réseau public aws ec2 associate-route-table \ --route-table-id rtb-xxxxxxxx \ --subnet-id subnet-xxxxxxxx

Route table privée :

# Créer une route table pour le sous-réseau privé aws ec2 create-route-table --vpc-id vpc-xxxxxxxx # Ajouter une route vers le NAT Gateway aws ec2 create-route \ --route-table-id rtb-xxxxxxxx \ --destination-cidr-block "0.0.0.0/0" \ --nat-gateway-id nat-xxxxxxxx # Associer au sous-réseau privé aws ec2 associate-route-table \ --route-table-id rtb-xxxxxxxx \ --subnet-id subnet-xxxxxxxx
Route 0.0.0.0/0 : la destination 0.0.0.0/0 signifie « toute adresse IP ». Pour les sous-réseaux publics, la route va vers l'IGW. Pour les privés, elle va vers le NAT Gateway.

8. Security Groups vs Network ACLs

Security Groups (pare-feu étatique)

  • Appliqués au niveau de l'instance.
  • ÉtatFULL (stateful) : si vous autorisez une connexion sortante, la réponse entre automatiquement.
  • Autorise ou refuse des connexions par paquet.
  • Un SG par défaut refuse tout et autorise la sortie.

Network ACLs (pare-feu stateless)

  • Appliqués au niveau du sous-réseau.
  • Stateless : une règle d'entrée n'autorise pas automatiquement la sortie correspondante.
  • Dispose de numéros de règle (1-32766) pour ordonner les évaluations.
  • Plus restrictif : bloque par défaut si aucune règle ne correspond.
# Créer un Security Group pour le web aws ec2 create-security-group \ --group-name "web-sg" \ --description "Accès HTTP/HTTPS/SSH" \ --vpc-id vpc-xxxxxxxx # Autoriser HTTP aws ec2 authorize-security-group-ingress \ --group-name "web-sg" \ --protocol tcp \ --port 80 \ --cidr "0.0.0.0/0" # Autoriser SSH (depuis votre IP seulement) aws ec2 authorize-security-group-ingress \ --group-name "web-sg" \ --protocol tcp \ --port 22 \ --cidr "192.168.1.0/24"
Sécurité : N'ouvrons jamais le port 22 (SSH) à 0.0.0.0/0. Restreignez-le à votre IP fixe ou utilisez AWS Session Manager pour un accès sans clé.

9. Test et validation

Lancez une instance EC2 dans le sous-réseau public et testez la connectivité :

# Lancer une instance dans le sous-réseau public aws ec2 run-instances \ --image-id ami-0c02fb0f4665ef278 \ --instance-type t2.micro \ --key-name mon-keypair \ --subnet-id subnet-xxxxxxxx \ --security-group-ids sg-xxxxxxxx \ --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=test-web}]' # Vérifier la connectivité HTTP curl http://<PUBLIC_IP>

Validation :

  • L'instance dans le sous-réseau public peut accéder à Internet (via IGW).
  • L'instance dans le sous-réseau privé peut accéder à Internet (via NAT Gateway) mais pas depuis Internet.
  • Les Security Groups bloquent tout sauf HTTP/HTTPS/SSH.

10. Bonnes pratiques

  • VPC personnalisé : Créez toujours un VPC personnalisé au lieu du VPC par défaut.
  • Séparation : Isoler les environnements (dev, test, prod) dans des VPC ou des VNet distincts.
  • NAT sain : Placez le NAT Gateway dans un sous-réseau public avec une IP élastique pour une haute disponibilité.
  • Sécurité en couches : Combinez Security Groups (allow list) et NACLs (deny list) pour une défense en profondeur.
  • Flow Logs : Activez VPC Flow Logs pour auditor le trafic réseau.
  • HA : Répartissez les sous-réseaux sur au moins 2 AZ pour la résilience.

11. Checklist imprimable

  • [ ] VPC créé avec CIDR approprié
  • [ ] 2 sous-réseaux publics dans des AZ différentes
  • [ ] 2 sous-réseaux privés dans des AZ différentes
  • [ ] Internet Gateway créée et attachée au VPC
  • [ ] NAT Gateway créé avec Elastic IP
  • [ ] Route table publique → IGW
  • [ ] Route table privée → NAT Gateway
  • [ ] Security Group configuré (SSH, HTTP, HTTPS)
  • [ ] VPC Flow Logs activé

12. Conclusion

Ce guide a présenté la création complète d'un VPC AWS avec une architecture trois-tiers (sous-réseaux publics et privés), un Internet Gateway et un NAT Gateway. Cette topologie offre :

  • Un contrôle total sur la topologie réseau et les flux de trafic.
  • Une sécurité en couches (SG + NACL + Firewall d'instance).
  • Une haute disponibilité grâce à la redondance multi-AZ.
  • Une isolation entre le web (public) et les données (privé).
