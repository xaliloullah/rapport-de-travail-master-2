1. Objectif

AWS IAM (Identity and Access Management) est le service qui permet de contrôler l'accès à toutes les ressources AWS de manière sécurisée. Ce guide vous apprendtra à :

  • Comprendre les concepts clés : utilisateurs, groupes, rôles et politiques.
  • Sécuriser le compte racine AWS avec MFA.
  • Créer des groupes IAM et appliquer le principe du moindre privilège.
  • Créer des utilisateurs et leur attribuer des politiques personnalisées.
  • Gérer IAM via l'interface graphique et l'AWS CLI.
Le principe du moindre privilège : Chaque utilisateur/ne/devrait n'avoir accès qu'aux ressources strictement nécessaires à ses fonctions. Jamais de droits administrateur global sauf cas exceptionnel.

2. Concepts clés IAM

Élément Description
Utilisateur (User) Compte unique pour une personne ou un service. Peut se connecter à la console AWS ou utiliser l'API.
Groupe (Group) Collection d'utilisateurs. Utile pour attribuer des politiques à plusieurs utilisateurs à la fois.
Rôle (Role) Identité ayant des permissions, mais sans clé d'accès permanente. Peut être assumé par un utilisateur ou un service AWS (ex. EC2).
Politique (Policy) Document JSON définissant les permissions (actions autorisées/refusées sur quelles ressources).
Bonne pratique : Utilisez des rôles pour les services AWS (EC2, Lambda...) plutôt que des clés d'accès. Les rôles sont temporaires et ne nécessitent pas de rotation manuelle.

3. Sécurisation du compte racine

Le compte racine AWS possède un accès complet à toutes les ressources. Il est critique de le sécuriser :

  1. Activer la MFA (Multi-Factor Authentication) sur le compte racine.
  2. Ne jamais utiliser le compte racine au quotidien.
  3. Créer un utilisateur IAM administrateur pour les tâches courantes.
  4. Supprimer les clés d'accès racine si elles existent.

Étapes — Activer la MFA :

  1. Connectez-vous à la console AWS avec le compte racine.
  2. Aller dans IAM → Utilisateurs → Mon compte racine.
  3. Cliquer sur Activer MFA.
  4. Choisir une application MFA (ex. Google Authenticator, Authy).
  5. Saisir les codes et confirmer.
Critique : Le compte racine ne doit jamais être utilisé pour des tâches courantes. Conservez ses identifiants très secrets et utilisez-le uniquement pour la configuration initiale et la récupération en cas d'urgence.

4. Création de groupes IAM

Les groupes permettent d'organiser les utilisateurs et d'appliquer des politiques à plusieurs utilisateurs d'un coup. Voici un schéma type :

Groupe Rôle Politique attachée
AdminGroup Administrateurs AdministratorAccess
Developers Développeurs Accès EC2, S3 en lecture, CloudWatch en lecture
ReadOnly Auditeurs / Consultants ReadOnlyAccess

Créer un groupe via AWS CLI :

# Créer un groupe aws iam create-group --group-name AdminGroup # Attacher une politique (administrateur) aws iam attach-group-policy \ --group-name AdminGroup \ --policy-arn arn:aws:iam::aws:policy/AdministratorAccess

5. Création et attribution de politiques

Les politiques IAM sont des documents JSON. Voici un exemple d'une politique personnalisée donnant un accès en lecture seulement à un bucket S3 spécifique :

{ "Version": "2012-10-17", "Statement": [ { "Effect": "Allow", "Action": [ "s3:GetObject", "s3:ListBucket" ], "Resource": [ "arn:aws:s3:::mon-bucket-s3", "arn:aws:s3:::mon-bucket-s3/*" ] } ] }
Structure d'une politique :
  • Version : toujours 2012-10-17.
  • Statement : liste des blocs de permissions.
  • Effect : Allow ou Deny.
  • Action : actions autorisées (ex. s3:GetObject).
  • Resource : ARN de la ressource ciblée.

Créer une politique personnalisée :

aws iam create-policy \ --policy-name "S3-lecture-mon-bucket" \ --policy-document file://politique-s3.json
Astuce : L'option file:// permet de charger un fichier JSON local au lieu de l'inscrire en ligne de commande. Très pratique pour les politiques complexes.

6. Création d'utilisateurs IAM

Créons un utilisateur et ajoutons-le à un groupe :

Étapes via la console :

  1. IAM → Utilisateurs → Ajouter un utilisateur.
  2. Saisir un nom (ex. dev-moussa).
  3. Cocher Accès programmatique (pour CLI/API) ou Accès à la console (pour la connexion web).
  4. Attacher le ou les groupes (ex. Developers).
  5. Télécharger les identifiants (clé + secret) une seule fois.

Créer un utilisateur via AWS CLI :

# Créer un utilisateur avec accès programmatique aws iam create-user --user-name dev-moussa # Attacher une politique directement à l'utilisateur aws iam attach-user-policy \ --user-name dev-moussa \ --policy-arn arn:aws:iam::aws:policy/AmazonS3ReadOnlyAccess # Ajouter l'utilisateur à un groupe aws iam add-user-to-group \ --group-name Developers \ --user-name dev-moussa
Important : Les clés d'accès (Access Key ID + Secret Access Key) doivent être stockées en sécurité et rotatées régulièrement. Si elles fuient, révoquez-les immédiatement via aws iam update-access-key --status Inactive.

7. Activation de la MFA pour les utilisateurs

La MFA (Multi-Factor Authentication) ajoute une couche de sécurité supplémentaire en exigeant un second facteur (application ou token matériel) en plus du mot de passe.

Activer la MFA via la console :

  1. IAM → Utilisateurs → Sélectionner l'utilisateur.
  2. Onglet Sécurité → Gestion des MFA.
  3. Lancer l'application MFA (ex. Google Authenticator) et saisir le code.
  4. Attribuer le MFA à l'utilisateur.

Activer la MFA via AWS CLI :

# Activer une MFA virtuelle aws iam create-virtual-mfa-device \ --virtual-mfa-device-name mfa-dev-moussa \ --outfile mfa-qr-code.png # Activer la MFA pour un utilisateur aws iam enable-mfa-device \ --user-name dev-moussa \ --serial-number arn:aws:iam::123456789012:mfa/dev-moussa \ --authentication-code1 123456 \ --authentication-code2 654321
Sécurité renforcée : La MFA est recommandée pour tous les utilisateurs IAM, surtout ceux ayant des droits administratifs ou un accès aux services sensibles (EC2, S3, IAM).

8. Gestion IAM via AWS CLI

Voici les commandes essentielles pour gérer IAM en ligne de commande :

# Lister tous les utilisateurs aws iam list-users # Lister les groupes aws iam list-groups # Lister les politiques attachées à un utilisateur aws iam list-attached-user-policies --user-name dev-moussa # Mettre à jour un utilisateur (changer le mot de passe) aws iam update-login-profile \ --user-name dev-moussa \ --password "NouveauMotDePasse123!" # Supprimer un utilisateur (révoquer les clés d'abord) aws iam delete-access-key --user-name dev-moussa --access-key-id AKIA... aws iam delete-user --user-name dev-moussa
Conseil : Utilisez aws iam simulate-principal-policy pour tester quelles actions un utilisateur peut effectuer avant de déployer une politique en production.

9. Bonnes pratiques IAM

  • Never use root : Ne jamais utiliser le compte racine pour les tâches quotidiennes.
  • MFA partout : Activez la MFA sur tous les utilisateurs, surtout les administrateurs.
  • Principle of least privilege : Attribuez le minimum de permissions nécessaires.
  • Politiques gérées vs personnalisées : Utilisez les politiques gérées AWS quand c'est possible (moins de risques d'erreurs).
  • Rotation des clés : Rotates les clés d'accès AWS toutes les 90 jours au maximum.
  • Auditer régulièrement : Utilisez AWS CloudTrail et IAM Access Analyzer pour vérifier les accès.
  • Rôles au lieu de clés : Pour EC2 et Lambda, utilisez des rôles plutôt que des clés d'accès.

10. Checklist imprimable

  • [ ] MFA activée sur le compte racine
  • [ ] Compte racine jamais utilisé au quotidien
  • [ ] Groupes IAM créés (AdminGroup, Developers, ReadOnly)
  • [ ] Politiques attribuées avec le principe du moindre privilège
  • [ ] Utilisateurs IAM créés avec mot de passe fort
  • [ ] MFA activée pour tous les utilisateurs IAM
  • [ ] Clés d'accès générées et stockées en sécurité
  • [ ] Politique de rotation des clés définie
  • [ ] CloudTrail activé pour l'audit IAM
  • [ ] Politique de blocage des clés racine définie

11. Conclusion

AWS IAM est la première couche de sécurité de votre environnement AWS. En maîtrisant les concepts (utilisateurs, groupes, rôles, politiques), en sécurisant le compte racine et en appliquant le principe du moindre privilège, vous réduisez considérablement le risque de violation de sécurité.
