Complément académique — AWS IAM

Identité, authentification, autorisation et gouvernance des accès.

1. Problématique

Dans un système distribué, la sécurité ne consiste pas seulement à protéger les serveurs : il faut déterminer qui peut agir, sur quelle ressource et dans quelles conditions. IAM formalise cette relation entre identité, action et ressource.

2. Modèle d'autorisation

Principal → Policy → Action → Resource → Condition.

Une policy JSON décrit les permissions. Les groupes simplifient l'administration des utilisateurs, tandis que les rôles permettent d'accorder des permissions temporaires à des services ou à des identités fédérées.

3. Principe du moindre privilège

Une permission doit être accordée uniquement lorsqu'elle est nécessaire. Il est préférable de cibler une ressource précise plutôt que d'utiliser systématiquement *. Les accès doivent être réévalués lorsque le rôle d'un utilisateur évolue.

aws sts get-caller-identity
aws iam list-users
aws iam list-roles

4. Sécurité du compte

  • Protéger le compte root et éviter son usage quotidien.
  • Activer MFA lorsque disponible.
  • Privilégier les rôles et les identifiants temporaires.
  • Surveiller les actions administratives.
  • Éviter les clés d'accès longues durées lorsqu'une alternative existe.

5. Analyse critique

IAM est une couche de gouvernance autant qu'un mécanisme technique. Une politique trop permissive augmente le risque ; une politique trop restrictive peut bloquer une application. La conception doit donc associer exigences fonctionnelles, modèle de menace, audit et tests.
