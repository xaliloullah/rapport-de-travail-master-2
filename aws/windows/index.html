1. Objectifs et contexte

Ce travail pratique a pour objectif de déployer une machine virtuelle Windows Server 2022 dans Amazon EC2, de comprendre son intégration au réseau AWS, puis de réaliser une connexion d'administration à distance.

La démarche couvre le cycle complet : choix de l'AMI, type d'instance, réseau, stockage EBS, paire de clés, Security Group, démarrage, récupération du mot de passe Administrator, connexion RDP, vérifications et sécurisation.

Résultat attendu : disposer d'une instance Windows Server 2022 fonctionnelle, joignable par RDP depuis une adresse IP autorisée, avec une configuration réseau et des accès administratifs maîtrisés.

2. Prérequis

2.1 Ressources nécessaires

  • Un compte AWS actif et une région AWS sélectionnée.
  • Un utilisateur ou rôle IAM autorisé à utiliser EC2.
  • Une paire de clés EC2 de type RSA pour une instance Windows.
  • Un poste client disposant d'un client RDP.
  • Une adresse IPv4 publique stable ou connue pour le poste administrateur.

2.2 Préparation de la sécurité

Le Security Group devra autoriser TCP 3389 uniquement depuis l'adresse IP publique de l'administrateur. AWS recommande de limiter les accès aux systèmes et emplacements de confiance. citeturn0search4turn0search12

2.3 Vérification locale

curl https://checkip.amazonaws.com

Cette commande permet d'obtenir l'adresse IPv4 publique observée par le service. On peut ensuite utiliser cette valeur avec le suffixe /32 dans une règle de Security Group.

3. Concepts et architecture

3.1 Amazon EC2

Amazon EC2 fournit des serveurs virtuels appelés instances. Une instance est définie notamment par une AMI, un type d'instance, un réseau, des volumes EBS, un Security Group et éventuellement un profil IAM.

3.2 AMI Windows

L'AMI Windows Server 2022 contient le système Windows et les composants AWS nécessaires au fonctionnement de l'instance. Les AMI Windows Server 2022 fournies par AWS utilisent notamment EC2Launch v2, AWS Systems Manager et les pilotes réseau/stockage adaptés à EC2. citeturn0search13

3.3 Architecture logique

Poste administrateur | | TCP 3389 / RDP v +---------------------------+ | Internet Gateway | +-------------+-------------+ | +-----v-----+ | VPC AWS | +-----+-----+ | +-----v----------------+ | Subnet publique | | Security Group | +-----+----------------+ | +-----v----------------+ | EC2 Windows Server | | Windows Server 2022 | | EBS + EC2Launch v2 | +----------------------+

3.4 Flux réseau

Le RDP utilise par défaut le port 3389/TCP. Le Security Group agit comme un pare-feu au niveau de l'instance et contrôle les flux entrants et sortants. citeturn0search5turn0search17

4. Installation et configuration

4.1 Création de la paire de clés

  1. Ouvrir EC2 → Network & Security → Key Pairs.
  2. Choisir Create key pair.
  3. Donner un nom, par exemple m2-windows-key.
  4. Sélectionner RSA, recommandé pour les instances Windows.
  5. Télécharger le fichier privé .pem et le conserver de manière sécurisée.

AWS précise que pour Windows, la paire RSA est utilisée notamment pour déchiffrer le mot de passe Administrator initial. citeturn0search10turn0search2

4.2 Création du Security Group

Créer un Security Group dédié, par exemple sg-m2-windows-rdp.

TypeProtocolePortSource
RDPTCP3389IP publique de l'administrateur/32

Ne pas utiliser 0.0.0.0/0 pour une administration RDP normale. Une règle RDP publique expose le service à Internet et augmente fortement la surface d'attaque.

4.3 Lancement de l'instance

  1. Ouvrir la console EC2 et choisir Launch instance.
  2. Choisir une AMI officielle Microsoft Windows Server 2022.
  3. Sélectionner un type d'instance adapté aux ressources nécessaires et au budget.
  4. Choisir le VPC et le subnet appropriés.
  5. Attribuer le Security Group RDP créé précédemment.
  6. Associer la paire de clés RSA.
  7. Configurer le volume racine EBS selon le besoin.
  8. Ajouter un tag Name=Windows-M2-UDB.
  9. Lancer l'instance.

5. Réalisation pratique

5.1 Vérifier l'état de l'instance

Attendre que l'état de l'instance soit Running et que les deux status checks soient valides.

aws ec2 describe-instances \ --filters "Name=tag:Name,Values=Windows-M2-UDB" \ --query 'Reservations[].Instances[].[InstanceId,State.Name,PublicIpAddress,PrivateIpAddress]' \ --output table

5.2 Récupérer le mot de passe Administrator

Dans la console EC2 : sélectionner l'instance → Connect → RDP → Get Password → sélectionner le fichier .pem → Decrypt Password. Pour les AMI Windows Server 2022, EC2Launch v2 génère le mot de passe initial. Le mot de passe peut nécessiter quelques minutes après le lancement avant d'être disponible. citeturn0search0turn0search3turn0search8

Le nom d'utilisateur dépend de la langue de l'AMI. Pour une AMI anglaise, il s'agit généralement de Administrator. citeturn0search3

5.3 Connexion RDP

  1. Dans EC2 → Connect → RDP, télécharger le fichier de connexion.
  2. Ouvrir le fichier avec le client Remote Desktop.
  3. Entrer le nom d'utilisateur Administrator approprié.
  4. Entrer le mot de passe déchiffré.
  5. Accepter l'avertissement de certificat si l'environnement de TP le justifie.

La connexion RDP classique nécessite une règle réseau permettant l'accès au port 3389. citeturn0search7turn0search9

5.4 Première configuration Windows

Après connexion, effectuer les contrôles suivants :

  • Vérifier le nom de la machine.
  • Vérifier la date et le fuseau horaire.
  • Vérifier l'adresse IP privée.
  • Vérifier l'espace disque disponible.
  • Installer les mises à jour Windows nécessaires.
  • Modifier le mot de passe Administrator initial et le stocker dans un gestionnaire de secrets sécurisé.

AWS recommande de changer le mot de passe Administrator initial après la première connexion, car le nouveau mot de passe ne peut ensuite plus être récupéré depuis la console EC2. citeturn0search0

6. Commandes et explications

6.1 Identifier une instance

aws ec2 describe-instances \ --filters "Name=tag:Name,Values=Windows-M2-UDB" \ --query 'Reservations[].Instances[].InstanceId' \ --output text

--filters limite la recherche aux instances correspondant au tag. --query extrait uniquement l'identifiant EC2.

6.2 Vérifier les status checks

aws ec2 describe-instance-status \ --instance-ids i-xxxxxxxxxxxxxxxxx \ --include-all-instances \ --query 'InstanceStatuses[].[InstanceId,InstanceState.Name,SystemStatus.Status,InstanceStatus.Status]' \ --output table

6.3 Arrêter ou démarrer une instance

aws ec2 stop-instances --instance-ids i-xxxxxxxxxxxxxxxxx aws ec2 start-instances --instance-ids i-xxxxxxxxxxxxxxxxx

L'arrêt d'une instance arrête le calcul facturé selon le modèle applicable, mais les ressources comme certains volumes EBS peuvent continuer à générer des coûts.

6.4 Créer un snapshot EBS

aws ec2 create-snapshot \ --volume-id vol-xxxxxxxxxxxxxxxxx \ --description "Sauvegarde TP Windows Server 2022"

Le snapshot sauvegarde un volume EBS. Il faut identifier le volume concerné avant d'exécuter la commande.

6.5 Vérifier les informations réseau

aws ec2 describe-instances \ --instance-ids i-xxxxxxxxxxxxxxxxx \ --query 'Reservations[].Instances[].[VpcId,SubnetId,PrivateIpAddress,PublicIpAddress,SecurityGroups[].GroupId]' \ --output table

6.6 Commandes Windows utiles

ipconfig /all hostname whoami systeminfo Get-Service -Name TermService Get-NetTCPConnection -LocalPort 3389 -State Listen Test-NetConnection -ComputerName localhost -Port 3389

Ces commandes permettent de vérifier respectivement le réseau, le nom de machine, l'utilisateur courant, les informations système, le service RDP et l'écoute locale du port 3389.

7. Vérifications et tests

7.1 Tests AWS

  • Instance : Running.
  • System status check : 2/2 checks passed lorsque les vérifications sont terminées.
  • Adresse IP publique présente si RDP direct est utilisé.
  • Security Group associé à l'instance.
  • Règle TCP 3389 limitée à l'IP administrative.

7.2 Tests Windows

Get-Service TermService Get-NetTCPConnection -LocalPort 3389 -State Listen Test-NetConnection localhost -Port 3389

Le résultat attendu est un service Remote Desktop actif et une écoute du port 3389 sur l'instance.

7.3 Test depuis le poste administrateur

Depuis Windows PowerShell :

Test-NetConnection <PUBLIC_IP> -Port 3389

La propriété TcpTestSucceeded doit être True lorsque le chemin réseau vers RDP est accessible.

AWS recommande également des outils Systems Manager pour diagnostiquer les problèmes RDP. L'automatisation AWSSupport-TroubleshootRDP peut vérifier ou corriger certains paramètres liés au port RDP, NLA et au pare-feu Windows. citeturn0search14

8.1 Alternative : Systems Manager

Pour une architecture plus sécurisée, une instance Windows peut être administrée via Systems Manager/Fleet Manager. Cette approche peut éviter d'exposer directement le port 3389 à Internet. Elle nécessite notamment que l'instance soit un managed node et que les permissions IAM et l'agent SSM soient correctement configurés. citeturn0search1turn0search9

9. Sécurité et bonnes pratiques

9.1 Accès

  • Activer MFA sur le compte root et les identités administratives.
  • Utiliser IAM avec le principe du moindre privilège.
  • Ne jamais stocker la clé .pem dans Git.
  • Restreindre RDP à des IP ou réseaux de confiance.
  • Privilégier Systems Manager lorsque l'architecture le permet.

9.2 Système

  • Installer régulièrement les mises à jour de sécurité Windows.
  • Changer le mot de passe Administrator initial.
  • Ne pas utiliser le compte Administrator pour les usages applicatifs courants.
  • Activer et surveiller les mécanismes de journalisation nécessaires.

9.3 Réseau

  • Limiter les règles Security Group au strict nécessaire.
  • Éviter les règles 0.0.0.0/0 pour RDP.
  • Pour une architecture de production, envisager des subnets privés et un RD Gateway, VPN ou une solution d'accès gérée.
  • Utiliser plusieurs couches de contrôle : Security Groups, NACLs et segmentation VPC lorsque nécessaire.

9.4 Coûts et cycle de vie

  • Arrêter les instances de TP lorsqu'elles ne sont plus utilisées.
  • Supprimer les ressources inutiles : volumes, snapshots et Elastic IP non nécessaires.
  • Configurer des alertes budgétaires AWS.
  • Utiliser des tags pour identifier propriétaire, environnement et projet.

Ces pratiques correspondent aux recommandations AWS de limitation des accès et de défense en profondeur pour les instances Windows. citeturn0search12

11. Conclusion

Ce travail pratique a permis de mettre en œuvre le déploiement d'un serveur Windows Server 2022 dans Amazon EC2. La démarche a couvert les éléments essentiels d'une infrastructure cloud : AMI, instance, VPC, subnet, Security Group, paire de clés, stockage EBS et accès distant RDP.

La réalisation ne se limite pas au lancement de la machine virtuelle. Un environnement professionnel doit également intégrer la vérification des status checks, le diagnostic réseau, la gestion des identités, la limitation des accès RDP, la mise à jour du système, la sauvegarde et la maîtrise des coûts.

Pour une architecture de production, l'étape suivante consiste à réduire l'exposition directe de RDP et à privilégier des mécanismes d'accès administré tels que AWS Systems Manager, ainsi qu'une architecture réseau segmentée.
