1. Objectifs et contexte

Ce travail pratique présente le déploiement d’un serveur Windows Server dans Amazon EC2, son intégration au réseau AWS et son administration à distance. EC2 fournit le serveur virtuel tandis que l’AMI Windows fournit le système d’exploitation et les composants nécessaires à son fonctionnement.

  • Créer une instance EC2 Windows à partir d’une AMI officielle.
  • Configurer VPC, subnet, Security Group, clé et stockage EBS.
  • Récupérer le mot de passe Administrator initial.
  • Établir une connexion RDP sécurisée.
  • Vérifier le système, le réseau et le service Remote Desktop.
  • Appliquer les principes de moindre privilège, de réduction de surface d’attaque et de maîtrise des coûts.
Résultat attendu : une instance Windows Server fonctionnelle, accessible uniquement depuis une source d’administration autorisée et correctement vérifiée.

2. Prérequis

Ressources AWS

  • Compte AWS actif et région sélectionnée.
  • Permissions IAM permettant l’utilisation d’EC2 et des ressources associées.
  • Paire de clés EC2 RSA conservée de manière sécurisée.
  • VPC et subnet adaptés, avec connectivité nécessaire.

Poste d’administration

  • Client RDP disponible, par exemple mstsc.exe sous Windows.
  • Adresse IP publique du poste administrateur lorsque RDP est exposé directement.
  • Accès à la console AWS ou à l’AWS CLI.

Paramètres réseau

À éviter : autoriser RDP depuis 0.0.0.0/0. Une règle publique expose directement le service RDP à Internet.

4. Installation et configuration

4.1 Créer la paire de clés

  1. EC2 → Key Pairs → Create key pair.
  2. Choisir un nom comme m2-windows-key.
  3. Sélectionner RSA.
  4. Télécharger le fichier privé .pem et ne jamais le publier.

4.2 Créer le Security Group

# Exemple conceptuel de règle RDP | TCP | 3389 | YOUR_ADMIN_IP/32

La source doit être l’adresse IP publique du poste d’administration ou un réseau privé de confiance. AWS indique que Windows utilise RDP et qu’une règle entrante appropriée doit être présente pour une connexion directe. citeturn0search0turn0search11

4.3 Lancer l’instance

  1. Choisir une AMI officielle Microsoft Windows Server 2022 ou une version retenue pour le TP.
  2. Sélectionner un type d’instance adapté à la charge.
  3. Choisir VPC et subnet.
  4. Associer le Security Group.
  5. Associer la paire de clés RSA.
  6. Configurer le volume racine EBS.
  7. Ajouter Name=Windows-M2-UDB.
  8. Lancer l’instance.

Une instance doit atteindre l’état running et réussir ses status checks avant la connexion. citeturn0search0

5. Réalisation pratique

5.1 Identifier l’instance

aws ec2 describe-instances \ --filters "Name=tag:Name,Values=Windows-M2-UDB" \ --query 'Reservations[].Instances[].[InstanceId,State.Name,PublicIpAddress,PrivateIpAddress]' \ --output table

5.2 Récupérer le mot de passe Administrator

Dans EC2 → sélectionner l’instance → Connect → RDP → Get Password. Charger la clé privée .pem, puis déchiffrer le mot de passe. AWS indique que le mot de passe initial peut nécessiter quelques minutes après le lancement avant d’être disponible. citeturn0search0

Le nom du compte Administrator dépend de la langue de l’AMI. Pour une AMI anglaise, le compte est généralement Administrator. citeturn0search0

5.3 Connexion RDP

  1. Télécharger le fichier RDP depuis la console EC2.
  2. Ouvrir mstsc.exe ou un client RDP compatible.
  3. Utiliser l’adresse DNS publique ou l’IP publique de l’instance.
  4. Saisir le compte Administrator et le mot de passe déchiffré.
  5. Vérifier l’empreinte du certificat lorsque l’environnement l’exige.

RDP utilise normalement TCP/3389. citeturn0search1

5.4 Première configuration

  • Vérifier le nom de la machine.
  • Vérifier le réseau et le stockage.
  • Installer les mises à jour Windows.
  • Changer le mot de passe Administrator initial.
  • Vérifier les services nécessaires.

AWS recommande de modifier le mot de passe Administrator initial après la première connexion. citeturn0search2

6. Commandes et explications

AWS CLI

# État et informations réseau aws ec2 describe-instances --instance-ids i-xxxxxxxxxxxxxxxxx \ --query 'Reservations[].Instances[].[State.Name,VpcId,SubnetId,PrivateIpAddress,PublicIpAddress]' \ --output table # Status checks aws ec2 describe-instance-status --instance-ids i-xxxxxxxxxxxxxxxxx \ --include-all-instances \ --query 'InstanceStatuses[].[InstanceId,InstanceState.Name,SystemStatus.Status,InstanceStatus.Status]' \ --output table # Arrêter / démarrer aws ec2 stop-instances --instance-ids i-xxxxxxxxxxxxxxxxx aws ec2 start-instances --instance-ids i-xxxxxxxxxxxxxxxxx

--instance-ids cible l’instance ; --query réduit la sortie aux informations utiles ; --output table facilite la lecture pendant le TP.

Commandes Windows / PowerShell

hostname whoami ipconfig /all systeminfo Get-Service -Name TermService Get-NetTCPConnection -LocalPort 3389 -State Listen Test-NetConnection -ComputerName localhost -Port 3389 Get-WinEvent -LogName System -MaxEvents 20

Ces commandes permettent respectivement de contrôler l’identité de la machine, l’utilisateur, la configuration réseau, le système, le service RDP, l’écoute du port 3389 et les événements système.

7. Vérifications et tests

7.1 Tests AWS

  • État EC2 : running.
  • Status checks : validés.
  • IP publique présente si RDP direct est utilisé.
  • Security Group associé et règle TCP/3389 limitée.

7.2 Tests Windows

Get-Service TermService Get-NetTCPConnection -LocalPort 3389 -State Listen Test-NetConnection localhost -Port 3389

7.3 Test depuis le poste administrateur

Test-NetConnection <PUBLIC_IP> -Port 3389

La propriété TcpTestSucceeded doit être True lorsque le chemin réseau est accessible.

9. Sécurité et bonnes pratiques

  • Activer MFA sur les identités humaines AWS.
  • Appliquer le moindre privilège IAM.
  • Ne jamais publier la clé .pem.
  • Limiter TCP/3389 à des sources de confiance.
  • Éviter 0.0.0.0/0 pour RDP.
  • Changer le mot de passe Administrator initial.
  • Maintenir Windows Server et les composants AWS à jour.
  • Privilégier Systems Manager lorsque possible.
  • Chiffrer et sauvegarder les volumes EBS selon les exigences du projet.
  • Surveiller les journaux et l’activité avec les services AWS adaptés.
  • Arrêter ou supprimer les ressources de TP inutilisées pour maîtriser les coûts.
Principe de défense en profondeur : l’accès RDP ne doit pas être la seule barrière. Il faut combiner IAM, segmentation VPC, Security Groups, durcissement Windows, journalisation et contrôle des identités.

11. Conclusion

Ce travail pratique a permis de mettre en œuvre un serveur Windows dans Amazon EC2 en couvrant les principales dimensions d’une infrastructure cloud : AMI, calcul, réseau, stockage, sécurité et accès distant.

La connexion RDP permet une administration graphique simple pour le TP, mais une architecture professionnelle doit réduire l’exposition directe du port 3389 et privilégier des mécanismes d’accès privés ou gérés lorsque cela est possible. AWS documente notamment RDP et les solutions Systems Manager/Fleet Manager pour l’administration des instances Windows. citeturn0search1turn0search5

La compétence acquise constitue une base pour les travaux suivants : hébergement Web Windows, IIS, Active Directory, automatisation PowerShell, Systems Manager et intégration avec les services DevOps AWS.
