Complément académique — Kubernetes

Approfondissement des concepts d'orchestration et d'administration de clusters.

1. Problématique

Lorsque le nombre de conteneurs augmente, leur lancement manuel devient difficile à maintenir. Kubernetes apporte une couche d'orchestration permettant de déclarer l'état souhaité d'une application et de laisser le cluster converger vers cet état.

2. Architecture logique

Utilisateur → API Server → état désiré → contrôleurs → nœuds → Pods → conteneurs.

Le control plane reçoit les déclarations et coordonne le cluster. Les nœuds exécutent les workloads. Le kubelet supervise les Pods et communique avec le plan de contrôle.

3. Objets déclaratifs

Deployment, Service, ConfigMap et Secret décrivent des responsabilités différentes. Un Deployment gère la disponibilité d'un ensemble de Pods ; un Service fournit un point d'accès stable ; ConfigMap et Secret séparent la configuration du code.

kubectl get nodes
kubectl get pods -A
kubectl describe deployment <nom>
kubectl rollout status deployment/<nom>

4. Disponibilité et mise à jour

Kubernetes peut remplacer progressivement les instances lors d'une mise à jour. Les probes de démarrage, de vivacité et de disponibilité permettent de distinguer un processus lancé d'un service réellement prêt à recevoir du trafic.

La stratégie doit être accompagnée de limites de ressources, de politiques de déploiement et d'une procédure de rollback.

5. Sécurité et gouvernance

  • Appliquer le principe du moindre privilège avec RBAC.
  • Éviter les conteneurs privilégiés.
  • Protéger les Secrets et contrôler leur exposition.
  • Limiter les ressources consommées par les workloads.
  • Tracer les opérations administratives.

6. Analyse critique

Kubernetes est puissant mais ajoute une forte complexité opérationnelle. Pour une petite application, cette complexité peut être disproportionnée. Le choix d'un orchestrateur doit donc dépendre du nombre de services, des exigences de disponibilité, des compétences de l'équipe et du niveau d'automatisation recherché.
